# パフォーマンス要件

## 最優先事項

**UI 応答性**。ユーザーに不快感を与えないよう軽快に動作することを最優先とし、
他の要件はこれに従属する。UI スレッドをブロックする実装は、
速度を問わず不可とする。

## レスポンスタイム目標

| 操作 | 目標 |
| --- | --- |
| ローカルデータベース操作 | 1 秒以内 |
| サーバー応答（単一タスク） | 5 秒以内 |
| 全体データ同期 | 10 分以内 |

## データ量

- アクティブタスク: 無制限
- アーカイブタスク: 無制限（アーカイブ DB で管理）

件数上限を設けない代わりに、**表示側で仮想スクロール（`ListView`）を必須** とする。
モバイルでは起動時の初期クエリに件数上限を設ける。

## オフラインと同期

- ローカルデータの即時反映を前提とし、同期の完了を待たない
- 同期はバックグラウンドで実行し、進捗を UI に表示する
- 差分同期は更新日時ベースで抽出し、1000 件単位でバッチ送信する
- **競合解決は Automerge (CRDT) に委ねる**。手動のマージ手順を設計しない

## ストレージ

- 添付ファイルは保存時に圧縮・リサイズする
- 低メモリ通知（モバイル）を受けたら、参照していない Automerge ドキュメントを解放する
