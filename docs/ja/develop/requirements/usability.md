# ユーザビリティ要件

## 1. キーボード操作

### 1.1 基本方針

- すべての機能をキーボードのみで操作可能
- マウス操作、キーボード操作、タッチ操作にいずれも対応する設計
- 効率的なワークフロー実現
- これらはすべて UI 層（`crates/flequit-ui`）で実装すること
- PCやサーバー向けにCLI版も作成する

#### 入力手段ごとの前提

| 入力手段 | 主な対象 | 要件 |
| --- | --- | --- |
| キーボード | デスクトップ | 全機能を操作可能。ショートカットはカスタマイズ可能 |
| マウス | デスクトップ | ホバーによる補助表示は可。ただしホバー必須の操作を作らない |
| タッチ | モバイル、タッチ対応 PC | 最小タップ領域 48px、長押しでコンテキストメニュー |

キーボードショートカットは `Capability` に依らず定義するが、
モバイルでは物理キーボード接続時のみ有効になる。
詳細は `../design/ui/responsive-layout.md` の「タッチ操作の要件」を参照。

### 1.2 ショートカットキー

初期設定は以下の通り、ユーザーが自分でカスタマイズできる。

- 基本操作
  - タスク作成: Ctrl+N
  - サブタスク作成: Ctrl+Shift+N
  - タスク編集: Enter
  - タスク削除: Delete, Backspace
  - 検索: Ctrl+F
  - 複製: Ctrl+D
- ナビゲーション
  - タスク間移動: ↑↓
  - サイドバー、タスク一覧、タスク詳細の移動: ←, →, Tabで→、Shift+Tabで← ※ループする
  - プロジェクト切替: Ctrl+P
  - タグ操作: Ctrl+T
  - vimモードもサポートする（hjklで移動）、オプションで設定可能
- カスタマイズ
  - ユーザー定義ショートカット
  - コマンドパレット対応
  - キーバインド設定UI

### 1.3 フォーカス管理

- 視覚的なフォーカス表示
- 論理的なフォーカス順序
- モーダル内フォーカストラップ
- フォーカス位置の保持

## 3. データ保護

### 3.1 未保存変更の確認

- **対象操作**
  - タスク詳細編集中の別タスク選択
  - サイドメニューでの画面切替
  - ウィンドウを閉じる操作（デスクトップ）
  - バックグラウンド遷移（モバイル。確認を出せないため後述の即時保存で対応する）

- **確認条件**
  - 編集モードで元データから変更がある場合のみ確認ダイアログを表示
  - 元データと完全一致する場合は確認不要で操作を継続

- **確認ダイアログ**
  - メッセージ: "未保存の変更があります。破棄してもよろしいですか？"
  - 選択肢: "保存して移動" / "破棄して移動" / "キャンセル"
  - キーボード操作: Escape でキャンセル、Enter で破棄して移動

- **動作仕様**
  - "保存して移動": 現在の変更を保存してから操作を実行
  - "破棄して移動": 変更を破棄して操作を実行
  - "キャンセル": 操作をキャンセルし編集モードを継続

### 3.2 編集中データの一時保存

- 編集中のデータは `flequit-platform::paths::cache_dir()` 配下へ一時保存する。
  ブラウザの `localStorage` は使わない（ネイティブアプリのため存在しない）
- アプリケーション異常終了時に復元する
- 自動保存間隔は設定可能とする

**モバイルでは終了通知が届かない**ため、確認ダイアログに依存した保護は成立しない。
永続化は操作のたびに完了させる
（[`../design/architecture.md`](../design/architecture.md) の
「アプリケーションライフサイクル」参照）。

## 4. カスタマイズ機能

### 4.1 ユーザー設定

- アニメーション制御
