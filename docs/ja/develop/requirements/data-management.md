# データ管理と同期の要件

本書は **要件**（何を満たすべきか）のみを定める。
保存先の構成・正となる保存先・層の割り当てといった **設計** は
[`../design/data/storage-targets.md`](../design/data/storage-targets.md) が正本
（2026-09-08 確定）。

## 要件

分散システムの考え方で構成し、**ローカルファースト**かつ様々な方法で
同期が取れること。

1. **保存先はユーザーが選ぶ**。アプリの種別（デスクトップ / モバイル / Web）が
   保存先を決めてはならない
2. **オフラインで書き込みが完結する**。ネットワークの状態が操作の成否を左右しない
3. **競合解決をユーザーに押し付けない**。複数端末・複数ユーザーの変更は
   自動でマージされる（Automerge の CRDT に委ねる）
4. **保存先の切り替えがデータ移行にならない**
5. **同期なしでも完全に動作する**。アカウント登録を必須にしない

## 保存先と実体

詳細な対応表と選定理由は
[`storage-targets.md`](../design/data/storage-targets.md) を参照。

| 保存先 | Desktop | Mobile | Web | 実体 | アカウント |
| --- | --- | --- | --- | --- | --- |
| ローカル | ○ | ○ | × | SQLite（検索）+ Automerge（永続化） | 不要 |
| クラウドストレージ | ○ | ○ | × | ユーザー所有の同期フォルダ上の Automerge ドキュメント | 任意 |
| バックエンドサーバ | ○ | ○ | ○ | Flequit が用意するサーバ（セルフホスト可） | 必須 |

- デスクトップ / モバイルは **ローカルが常に正**。クラウドストレージと
  バックエンドサーバは同期先であり、0 個以上を併用できる
- **Web はブラウザ内に何も保存しない**。バックエンドサーバが正となり、
  オフラインでは動作しない。IndexedDB / OPFS 上の Repository 実装は作らない
  （`plans/plan.md` 7.）

## 暗号化

全 Automerge ドキュメントを暗号化状態で保存する。
鍵管理・アクセス制御・失効の設計は
[`../design/data/data-security.md`](../design/data/data-security.md) を参照。

## 未採用・未決の案

- **Git 同期**: Git 管理可能なサービスを同期先にする案。
  実現するなら「同期フォルダが Git リポジトリであるクラウドストレージ」として
  扱い、保存形式は Automerge のままとする。
  タスク 1 件につき 1 JSON ファイルを置く旧設計（Svelte 版）は採用しない。
  `architecture.md` に将来の選択肢として記載があるのみで、着手予定はない
- 認証方式、同期の粒度・起動契機、複数同期先の失敗時の扱いは未設計
  （`plans/plan.md` 8.「決めるべきこと」）
