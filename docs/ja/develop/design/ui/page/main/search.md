# 検索とタスク一覧の絞り込み

メイン画面のタスク一覧は、サイドバー上部の検索ボックスに入力したクエリだけで決まる。
サイドバーの期限ボタン・状態ボタン・プロジェクト・リスト・タグブックマークは、
クエリを書き換える手段として働く。

- 画面全体の構成: [メイン画面](./main.md)
- 実装: `crates/flequit-ui/src/viewmodels/search/`、`crates/flequit-ui/src/viewmodels/app.rs`

## 1. 基本方針

1. **クエリが唯一の状態**。タスク一覧は常に「全タスク（アーカイブ・削除済みを除く）を
   クエリで絞り込んだ結果」とする。サイドバーの操作はクエリを書き換える手段にすぎない
2. **見た目は短く、データは明確に**。入力欄には `@山田` と見せ、内部では `@user:{UserId}` のように
   対象の種類と実体を確定させて持つ
3. **利用者に ID を見せない**。同名の区別は、候補から選ぶ操作で行う
4. **どの言語の表記でも入力を受け付け**、表示は UI 言語の表記にする
5. **入力途中で一覧が空にならない**（既存方針を維持）。解釈できない部分は無視し、その旨を表示する

## 2. クエリの 2 層構造

### 2.1 表示文字列と内部クエリ

| 層 | 誰が見るか | 例 |
| --- | --- | --- |
| 表示文字列 | 利用者（検索ボックスの中身） | `(@今日 \| @期限切れ) @山田 -@完了 牛乳` |
| 内部クエリ | ViewModel、保存データ | `(@due:today \| @due:overdue) @user:{山田の UserId} -@status:completed 牛乳` |

- 内部クエリは**言語に依存しない**。期限・状態・種類名はキー（`today`、`completed`、`project`）で持つ
- 内部クエリで対象を指す書き方（**参照**）:

  | 種類 | 内部の書き方 | 表示の例（ja） |
  | --- | --- | --- |
  | 期限 | `@due:today` `@due:3d` `@due:10min` | `@今日` `@3日` `@10分` |
  | 状態 | `@status:completed` `@status:open` | `@完了` `@未完了` |
  | プロジェクト | `@project:{プロジェクト ID}` | `@仕事` |
  | リスト | `@list:{リスト ID}` | `@仕事.今週やる` |
  | ユーザー | `@user:{UserId}` | `@山田`（表示名） |

  プロジェクトとリストは同名を許すため、内部では ID で持つ。
  ユーザーは `handle_id` を後から変更できるようにする可能性があるため、`UserId` で持つ。
  入力は表示名と `handle_id` のどちらでも受け付ける（`@山田`、`@user:yamada`）
- タグ `#名前`、テキスト属性（`@note:` など）、自由語、演算子、括弧は、表示と内部で同じ文字列をそのまま持つ。
  タグは `#` で入力するもので、本仕様の `@` の仕組み（確定・曖昧・参照）には乗せない

### 2.2 トークンの状態

表示文字列の中の `@...` の各トークンは、次のいずれかの状態を持つ。

| 状態 | 意味 | 絞り込みでの扱い | 見た目 |
| --- | --- | --- | --- |
| **確定** | 対象が 1 つに決まっている（内部に参照を持つ） | その対象 | 通常 |
| **入力中** | 直前の編集位置がトークンの中（末尾を含む）にあり、まだ打っている | 名前で仮に解決した結果（下記） | 通常 |
| **曖昧** | 名前に当たる対象が複数あり、まだ選ばれていない | 候補すべての和集合（一覧が空にならないように） | 警告アイコン |
| **未解決** | 当たる対象がない | 無視 | 警告アイコン |

- 入力中・入力完了時の名前での解決は 3.4 のとおり
- **確定のタイミング**: トークンの外で次の編集をした（空白・演算子・括弧を打った場合を含む）、`Enter`、
  入力候補から選んだ、サイドバーでクエリを操作した、のいずれか
  - Slint の `LineEdit` はキャレット位置を公開していないため、「入力中」は直前の編集位置で判定する。
    フォーカスが外れたことも検知しないので、打ちかけのトークンは入力中のまま残り、名前で仮に解決される
  - 候補が 1 つ → そのまま確定
  - 候補が複数 → **曖昧さ解消の一覧**を開く（6.2）。選べば確定、`Esc` なら曖昧のまま残す
  - 候補がない → 未解決
- サイドバー操作・入力候補から入ったトークンは、最初から確定している
- 確定したトークンの文字を 1 文字でも書き換えたら、確定を外して入力中に戻す
- 検索ボックス横の警告アイコンを押すと、残っている曖昧なトークンの一覧を再び開く

### 2.3 表示文字列の作り方

確定したトークンの表示は、内部の参照から次の規則で作る。

- 基本は `@名前`。リストは `@プロジェクト名.リスト名`
- 表示文字列を**名前だけで解決し直したとき、同じ種類の候補が含まれる最短の形**にする。
  たとえばプロジェクト「今日」は `@今日` だと期限と衝突するが、衝突は曖昧さ解消で扱えるので
  表示は `@今日` のままでよい。種類を明示した表示（`@プロジェクト:今日`）にするのは、
  利用者が `@プロジェクト:` と打って確定させた場合だけとする（打った形を尊重する）
- 名前に空白・記号・`.` を含む場合は引用する（`@"My Project"`、`@"v1.2"."バグ"`）
- 同名のプロジェクト 2 つは、どちらも `@仕事` と表示される。**区別は内部の参照が持つ**。
  どちらを指しているかは、サイドバーのハイライト（4.5）で確認できる

### 2.4 改名・削除・言語切替への追従

内部で参照を持つので、表示文字列を作り直すだけで追従できる。

- プロジェクト / リスト / ユーザーの**改名**: 確定したトークンの表示を新しい名前で作り直す。
  同期（Automerge）で別の端末の改名が届いた場合も同じ
- **削除**: トークンは表示を残したまま未解決にする（勝手に消すと条件が緩んで一覧が増えるため）
- **UI 言語の切替**: 確定した期限・状態・種類名のトークンを新しい言語で作り直す。
  自由語・タグ・演算子・空白には触れない
- タグ（`#タグ名`）は本仕様の対象外で、現行の挙動を変えない

### 2.5 コピー & ペースト

- コピーされるのは表示文字列（Slint の `TextInput` の標準動作）
- 貼り付けた `@...` は入力中として扱い、確定のタイミングで名前から解決し直す。
  別の端末や他人に渡しても、名前が同じなら同じ意味になる

## 3. 構文

表示文字列（利用者が打つもの）の構文。内部クエリも同じ文法で、参照の書き方だけが違う。

### 3.1 トークン

| 種別 | 書式 | 例 | 意味 |
| --- | --- | --- | --- |
| 名前（省略形） | `@<名前>` | `@今日` `@完了` `@仕事` `@山田` | 期限 / 状態 / プロジェクト / リスト / ユーザーから探す（3.4） |
| 名前（修飾） | `@<プロジェクト>.<リスト>` | `@仕事.今週やる` | 指定プロジェクト内の指定リスト |
| 種類の明示 | `@<種類>:<名前>` | `@user:yamada` `@プロジェクト:今日` | 種類を固定して完全一致。`*` で部分一致（`@project:*仕*`） |
| テキスト属性 | `@<属性>:<値>` | `@note:牛乳` | 既存の `@task:` `@note:` `@subtask:` `@subtasknote:`。部分一致のまま |
| タグ | `#<タグ名>` | `#買い物` | 既存どおり前方一致 |
| 自由語 | それ以外 | `牛乳` | タスク名・ノートの部分一致。サブタスクは 3.7 のとおり |
| 引用 | `"..."` | `"牛乳 2本"` `@"My Project"` | 空白・記号・`.` を含む名前や語句。`\"` でエスケープ |

- 比較は大文字小文字を区別せず、**NFKC 正規化**（全角英数 ↔ 半角、半角カナ → 全角）した上で行う
- 区切りの空白には全角空白も含める
- 記号 `@ # ( ) | " . :` は全角（`＠ ＃ （ ） ｜ ＂ ． ：`）も同じ意味として扱う。IME オンのまま入力できるようにするため

### 3.2 演算子

| 演算 | 書式 | 例 |
| --- | --- | --- |
| AND | 空白（暗黙）、または `AND` | `@今日 #仕事` = `@今日 AND #仕事` |
| OR | `\|`、または `OR` | `@今日 \| @期限切れ` |
| NOT | `-` 前置、または `NOT` | `-@完了` `NOT @仕事` |
| グループ | `( )` | `(@今日 \| @期限切れ) #仕事` |

- 優先順位: `NOT` > `AND` > `OR`（一般的な検索エンジン・論理式と同じ）
- 演算子の単語 `AND` / `OR` / `NOT` は**大文字の英語のみ**。小文字の `or` や日本語の「または」は自由語として扱う。
  演算子を言語ごとに翻訳すると自由語と衝突する（「または」を含むタスク名を検索できなくなる）ため、
  記号 `|` `-` `( )` を正式な表記とし、英単語は補助とする
- 先頭が `-` の語を自由語として検索したい場合は引用する（`"-foo"`）

### 3.3 文法（EBNF）

```text
query    = [ or_expr ] ;
or_expr  = and_expr , { or_op , and_expr } ;
and_expr = unary , { [ "AND" ] , unary } ;
unary    = ( "-" | "NOT" ) , unary | primary ;
primary  = "(" , or_expr , [ ")" ] | term ;      (* 閉じ括弧の省略を許す *)
or_op    = "|" | "OR" ;
term     = "@" , keyword | "#" , tag | text ;
```

### 3.4 名前での解決

`@X`（省略形）は、次の全種類から**完全一致**するものを集める。

| 順 | 種類 | 照合先 |
| --- | --- | --- |
| 1 | 期限 | 期限キーワード（全言語の表記） |
| 2 | 状態 | 状態キーワード（全言語の表記、3.5） |
| 3 | プロジェクト | プロジェクト名 |
| 4 | リスト | リスト名（全プロジェクト横断） |
| 5 | ユーザー | 表示名、`handle_id` |

- 候補が 1 つ → 確定。複数 → 曖昧さ解消の一覧（6.2）。「順」は一覧での並び順
- `@P.L` はまず `P.L` 全体を 1 つの名前として試し、当たらなければ最初の `.` で分割してリストを探す
- `@<種類>:X` は、その種類だけから探す。種類名は語彙表（5.1）で多言語化する

  | 種類 | 英語 | 日本語 |
  | --- | --- | --- |
  | 期限 | `due:` | `期限:` |
  | 状態 | `status:` | `状態:` |
  | プロジェクト | `project:` `proj:` | `プロジェクト:` |
  | リスト | `list:` | `リスト:` |
  | ユーザー | `user:` | `ユーザー:` `担当:` |

- `*` を含めると部分一致になる（`@project:*仕*`、`@list:今週*`）。
  部分一致のトークンは 1 つに確定させず、**当たった全対象の和集合**として扱う（曖昧さ解消の一覧は出さない）
- **入力中**（直前の編集位置がトークンの中）は、名前がその時点で完全一致する候補の和集合で仮に絞り込む。
  完全一致がなければ無視する（`@仕` と打っている途中で一覧が空にならないように）

### 3.5 状態キーワード

| 意味 | 内部キー | ja | en |
| --- | --- | --- | --- |
| 完了 | `completed` | `@完了` `@完了済み` | `@done` `@completed` |
| 未完了（完了・中止以外） | `open` | `@未完了` | `@open` `@todo` |
| 未着手 | `not-started` | `@未着手` | `@not-started` |
| 実行中 | `in-progress` | `@実行中` `@進行中` | `@in-progress` `@doing` |
| 待機中 | `waiting` | `@待機中` | `@waiting` |
| 中止 | `cancelled` | `@中止` | `@cancelled` `@canceled` |

- ドメインの `TaskStatus`（5 状態）に対応する。`open` だけは複数の状態をまとめたもの
- タスクとサブタスクの両方に効く（3.7）
- 期限の `@期限切れ` は、これまでどおり完了済みを含まない

### 3.6 エラーと入力途中の扱い

| 状況 | 扱い |
| --- | --- |
| `@` だけ、`@to`、`#` だけ、`-` だけ | その項を無視（既存どおり） |
| 未解決の `@X` | 無視し、警告アイコンを出す。ツールチップで無視した語を列挙する |
| 曖昧なまま残した `@X` | 候補の和集合で絞り込み、警告アイコンを出す |
| `(` の閉じ忘れ | 末尾で閉じたものとみなす |
| 余分な `)`、先頭 / 末尾 / 連続した `\|` | 無視し、警告アイコンを出す |
| 空の括弧 `()` | 無視 |

### 3.7 タスクとサブタスクの評価

サブタスクもタスクと同じく状態・期限・担当者を持つので、**タスクとサブタスクをそれぞれ 1 件の検索対象**として、
クエリ全体で評価する。

#### 3.7.1 各検索対象が持つ値

| 条件 | タスク | サブタスク |
| --- | --- | --- |
| 期限 `@今日` など | 自分の期限 | 自分の期限（`plan_end_date`）。**親からは継承しない** |
| 状態 `@完了` など | 自分の状態 | 自分の状態 |
| 担当 `@山田` | 自分の担当者 | 自分の担当者 |
| プロジェクト / リスト | 所属 | 親タスクの所属を継承 |
| タグ `#` | 自分のタグ | 自分のタグ ∪ 親タスクのタグ |
| 自由語 | 自分の名前・ノート | 自分の名前・ノート ∪ 親タスクの名前・ノート |
| `@task:` / `@note:` | 自分の名前 / ノート | 親タスクの名前 / ノート |
| `@subtask:` / `@subtasknote:` | 配下のいずれかのサブタスクの名前 / ノート（現行どおり） | 自分の名前 / ノート |

- 所属・タグ・自由語を継承するのは、`@仕事 牛乳 冷蔵庫`（タスク「牛乳を買う」のサブタスク「冷蔵庫を確認」）
  のように、親と子にまたがる条件で現行どおり見つけられるようにするため
- 期限・状態・担当を継承しないのは、「今日が期限のサブタスク」「山田さん担当のサブタスク」を正しく拾うため。
  継承すると、親が今日期限なら全サブタスクが `@今日` に当たってしまう
- **1 件の中で全条件を満たす必要がある**。`@山田 @今日` は「山田さん担当で今日期限」のタスク、
  またはそういうサブタスクに当たる。「タスクは今日期限、サブタスクは山田さん担当」の組み合わせでは当たらない
- NOT も 1 件ごとに評価する。`-@完了` は「完了していないタスク、または完了していないサブタスク」に当たる

#### 3.7.2 一覧での見せ方

一覧の行は従来どおりタスク単位とする。

| 当たったもの | 行の表示 |
| --- | --- |
| タスク自身 | 通常どおり表示する |
| タスク自身は外れ、サブタスクだけが当たった | タスクの行を表示し、自動で展開して、当たったサブタスクだけを強調する。タスクの行には「サブタスク N 件が一致」と表示し、タスク自身は薄く表示する |
| タスク自身もサブタスクも当たった | 通常どおり表示する。サブタスクには印を付けない（所属や自由語を継承するため、タスクが当たると多くのサブタスクも当たり、印が意味を持たなくなる） |

- 自動展開は検索の結果による一時的なもので、利用者が開閉した状態（`task_ui`）は上書きしない。
  クエリが空になったら元の開閉状態に戻る
- 期限ボタンの件数は、**行の数**（当たったサブタスクを持つタスクを含む）を数える
- 手動の並び替え（D&D）は、薄く表示したタスクの行も対象にする

## 4. サイドバー操作

### 4.1 クリックで書き込むトークン

いずれも確定した状態で書き込む。

| 項目 | 表示（ja） | 表示（en） | 内部 |
| --- | --- | --- | --- |
| 期限ボタン | `@今日` | `@today` | `@due:today` |
| カスタム期限ボタン | `@10分` | `@10min` | `@due:10min` |
| 状態ボタン（新設） | `@未完了` | `@open` | `@status:open` |
| プロジェクト | `@仕事` | 同左 | `@project:{ID}` |
| リスト | `@仕事.今週やる` | 同左 | `@list:{ID}` |
| タグブックマーク | `#買い物` | 同左 | 同左 |

### 4.2 操作と結果

「主修飾キー」は macOS では Command、それ以外では Ctrl。「副修飾キー」は macOS では Option、それ以外では Alt。
以下、クエリ `Q` に対して項目のトークン `X` を操作する。

| 操作 | 動作 | 結果の例（Q = `@今日 \| @期限切れ`、X = `@仕事`） |
| --- | --- | --- |
| クリック | **置き換え** | `@仕事` |
| 主修飾キー + クリック | **AND で追加** | `(@今日 \| @期限切れ) @仕事` |
| 副修飾キー + クリック | **OR で追加** | `@今日 \| @期限切れ \| @仕事` |
| コンテキストメニュー「除外する」 | **NOT で追加** | `(@今日 \| @期限切れ) -@仕事` |
| コンテキストメニュー「条件から外す」 | X を含む項を**取り除く** | — |

- AND で追加するとき、既存クエリのトップレベルに OR があれば括弧で囲む。
  囲まずに後ろへ付けると優先順位で `@今日 | (@期限切れ @仕事)` になってしまうため
- OR で追加するときは括弧は不要（`A B | X` は優先順位どおり `(A B) | X` になる）
- **トグル**: X がすでにトップレベルの AND 項にあるとき主修飾キー + クリックすると取り除く。
  トップレベルの OR 項にあるとき副修飾キー + クリックすると取り除く
- **クリア**: クエリが X だけのときにクリックすると、クエリを空にする（現行の期限ボタンの挙動を全項目に揃える）
- 「同じ X か」は内部の参照で比べる（同名の別プロジェクトは別物）
- 置き換え・追加のあとはキャレットを末尾に置き、入力候補を閉じる。
  狭い幅でサイドバーがオーバーレイ表示なら閉じる（現行どおり）

### 4.3 コンテキストメニュー

デスクトップでは右クリック、タッチ操作では長押しで開く。期限ボタン、状態ボタン、プロジェクト、
リスト、タグブックマークの全項目で同じ内容を出す。

| メニュー項目 | 動作 | 選べる条件 |
| --- | --- | --- |
| この条件だけで表示 | 置き換え | 常に |
| AND で追加（Ctrl/⌘ + クリック） | AND で追加 | 常に（クエリが空なら置き換えと同じ結果） |
| OR で追加（Alt/⌥ + クリック） | OR で追加 | 常に（同上） |
| 除外する | NOT で追加 | 常に |
| 検索条件から外す | 取り除く | 項目がハイライトされている（クエリのトップレベルの項にある） |

- 対応するクリック操作は、OS を問わない表記で項目名に含める（`Ctrl/⌘`、`Alt/⌥`）
- プロジェクト / リストの編集・リスト追加は、これまでどおり行の右端のボタンで行う
- **狭い幅（スマホ）では修飾キーを使えないため、メニューが追加操作の唯一の手段**になる。
  タップは置き換え、長押しでメニュー

### 4.4 キーボードと OS の差

- スクリーンリーダーの既定のアクションはクリック（置き換え）と同じ
- サイドバーの項目はキーボードでフォーカスできないため、キーボードだけで AND / OR を追加する手段はまだない
  （フォーカスできるようにしたうえで、主修飾キー + `Enter` = AND 追加、副修飾キー + `Enter` = OR 追加、
  `Menu` キー = コンテキストメニューとする予定。`plans/plan.md` の残作業）
- Slint は Apple 系の OS で Command と Ctrl を入れ替えて渡す（Qt と同じ扱い）。そのため
  `KeyboardModifiers.control` がどの OS でも「主修飾キー」になり、`alt` が「副修飾キー」になる。
  OS による分岐はアプリ側に要らない
- Linux の一部のデスクトップ環境では Alt + クリックがウィンドウ移動に使われ、アプリに届かない。
  その環境ではコンテキストメニューで代替する（既知の制約として記載する）
- コンテキストメニューは Slint の `ContextMenuArea` で作る。右クリックと `Menu` キーで開き、Android では長押しで開く

### 4.5 サイドバーのハイライト

内部クエリの参照から導出する。名前ではなく参照で比べるので、同名のプロジェクトの片方だけが光る。

- トップレベルの AND 項にある項目 → **強いハイライト**（`@今日 @仕事` なら「今日」と「仕事」の両方）
- トップレベルの OR 項にある項目 → **弱いハイライト**
- NOT の項 → 「除外中」の表示（取り消し線など）
- 括弧の奥の項ではハイライトしない（「その項目で絞り込んでいる」とは言えないため）
- 曖昧なトークンの候補はハイライトしない
- リストが対象のときは、親プロジェクトを展開する

## 5. 多言語対応

### 5.1 語彙の持ち方

- 期限・状態のキーワードと種類名の表記は **Rust 側の表**に持つ（`.po` には置かない）。
  入力は UI 言語に関係なく**全言語の表記を同時に受け付ける**必要があり、
  `.po` は「キー → 現在言語の訳」の片方向しか引けないため
- 表は「内部キーごとに、各言語の**正規表記 1 つ + 別表記の一覧**」を持つ

  | 内部キー | ja 正規 | ja 別表記 | en 正規 | en 別表記 |
  | --- | --- | --- | --- | --- |
  | `due:today` | `今日` | `本日` | `today` | — |
  | `due:overdue` | `期限切れ` | — | `overdue` | `deadline` |
  | `due:{N}d` | `{N}日` | — | `{N}days` | `{N}day` |
  | `due:{N}min` | `{N}分` | — | `{N}min` | `{N}minutes`, `{N}minute` |
  | `status:completed` | `完了` | `完了済み` | `done` | `completed` |
  | 種類 `user` | `ユーザー:` | `担当:` | `user:` | — |

- 言語を追加したら表に列を足す。「全てのキーに全言語の正規表記がある」ことをテストで保証する
- 演算子（`AND` `OR` `NOT` `|` `-`）は翻訳しない（3.2）

### 5.2 表示と保存

- 確定したトークンの表示は、常に**UI 言語の正規表記**で作る。言語を切り替えたら作り直す（2.4）
- 保存するのは内部クエリなので、保存データは言語に依存しない
- 設定に保存している期限ボタンの `query`（現状 `"@today"` 固定）はキーだけを保存する形へ移行する

### 5.3 翻訳が必要な UI 文言（`.po`）

- 検索ボックスのプレースホルダー、警告のツールチップ（「解釈できない条件: …」「候補が複数あります」）
- 入力候補と曖昧さ解消の一覧の種類ラベル（期限 / 状態 / プロジェクト / リスト / ユーザー）と説明
- コンテキストメニュー（4.3 の各項目とショートカット表記）
- 追加先ピッカー（7.1）
- 読み上げ用の件数（「N 件のタスク」）

## 6. 入力候補と曖昧さ解消

### 6.1 入力候補（打っている間）

既存の入力候補（末尾トークンが対象）を拡張する。

- `@` の後: 期限・状態キーワード（UI 言語の正規表記）、プロジェクト、`プロジェクト.リスト`、ユーザー。
  部分一致で絞り込む
- `@project:` などの種類の後: その種類だけ
- `@P.` の後: P のリスト
- `#` の後: タグ（既存どおり）
- `(` `|` `-` の直後でも同じ候補を出す
- 各候補には**種類のラベルと区別の手がかり**を付ける

  | 種類 | 手がかり |
  | --- | --- |
  | プロジェクト | 色の点、リスト数、アーカイブ済みか |
  | リスト | 所属プロジェクト名と色 |
  | ユーザー | アバター、表示名と `@handle_id` |
  | 期限 / 状態 | 説明（「今日が期限」など） |

- 候補を選ぶと、そのトークンを**確定した状態で**置き換える。同名が複数あっても、選んだものに確定する

### 6.2 曖昧さ解消の一覧（打ち終えたとき）

候補から選ばずに `@山田` と打ち終えて、ユーザー「山田」とプロジェクト「山田」の両方に当たった場合に出す。

```text
 @山田 ▏
┌─────────────────────────────────┐
│ 「山田」が複数見つかりました      │
│ ● プロジェクト  山田  (リスト 3)   │
│ 👤 ユーザー     山田 太郎 @yamada  │
│ ● プロジェクト  山田  (アーカイブ) │
└─────────────────────────────────┘
```

- 並び順は 3.4 の「順」、同じ種類の中は名前順
- 選び方は 6.3 のとおり。`Esc` で閉じると曖昧のまま残る（和集合で絞り込む）
- 6.1 の入力候補と同じ部品・同じ見た目で作る。開いている間は 6.1 の入力候補より優先して表示する

### 6.3 表示とキー操作

入力候補（6.1）と曖昧さ解消の一覧（6.2）は、ポップアップではなく**検索ボックスの直下にインラインで**表示する。
表示中はサイドバーの中身がその分だけ下へずれる。

- Slint の `PopupWindow` は開くとキーボードフォーカスを奪う。ポップアップで出すと、`@` を打った直後に
  キャレットが検索ボックスから外れ、続けて入力できなくなる（2026-09-19 の実機確認で判明し、修正した）
- キーボードフォーカスは常に検索ボックスに残る。一覧は次のキーだけを受け取り、それ以外は検索ボックスの通常の編集になる

  | キー | 動作 |
  | --- | --- |
  | ← / → | キャレット移動（検索ボックスの通常動作） |
  | ↑ / ↓ | 一覧の選択を移動する。選択行が表示範囲の外に出る場合は一覧をスクロールして追従する |
  | `Enter` | 一覧が開いていれば選択中の候補で確定する。開いていなければ入力中の語を確定する（2.2） |
  | `Esc` | 一覧を閉じる。入力候補は次に文字を打つと再び開く。曖昧さ解消の一覧は警告アイコンで開き直す |

- クリックでも選べる。候補の行はフォーカスを取らないため、クリック後も検索ボックスで入力を続けられる
- 一覧は最大 7 行分の高さで、それを超える候補はスクロールする

## 7. 付随する挙動

### 7.1 タスクの追加先ピッカー

一覧はクエリで決まり、「どのリストを見ているか」が一意に決まらない。
そのためタスク追加欄に**追加先ピッカー**を置き、追加先を常に見える形で選べるようにする。

```text
┌───────────────────────────────────────────────┐
│ [● 仕事 › 今週やる ▾]  新しいタスクを入力…      │
└───────────────────────────────────────────────┘
```

- 追加欄の左にボタン（プロジェクトの色の点 + `プロジェクト › リスト ▾`）を置き、押すとピッカーを開く
- ピッカーの中身: 絞り込み用の入力欄、「最近使った追加先」（最大 5 件）、プロジェクト → リストのツリー。
  同名のプロジェクトは色とリスト数で区別する。アーカイブ済みは出さない
- **既定の追加先**（ピッカーを触っていないときの値）:
  1. 内部クエリの**トップレベルの AND 項にリストの参照が 1 つだけ**あれば、そのリスト
  2. プロジェクトの参照が 1 つだけあれば、そのプロジェクトで最後に使ったリスト（なければ先頭のリスト）
  3. それ以外は最後に使った追加先。なければ先頭プロジェクトの先頭リスト
- ピッカーで手で選んだ追加先は、**クエリの変更で既定値が変わるまで**保持する。
  クエリを変えるたびに手で選んだ値が上書きされるのを防ぎつつ、`@仕事.今週やる` をクリックしたら追加先も追従させるため
- ピッカーでの選択はクエリを変えない（追加先と表示条件は独立）
- 追加したタスクがクエリに合わないときも、追加直後の 1 件は一覧に残す（追加したのに見えない、を避ける）。
  次にクエリを変えた時点で、クエリどおりの一覧に戻る
- ピッカーは追加欄の上へ開くポップアップとする（追加欄が一覧の下端にあるため）。狭い幅でも同じ
- 詳細ペインでのタスクの移動（リスト間 / プロジェクト間）は別機能として扱い、本件には含めない

### 7.2 クエリの保持

- **内部クエリ**を端末ごとのユーザー設定（`UserSettings`）へ保存し、起動時に復元する。
  表示文字列は起動時に作り直す（停止中の改名や言語切替もこれで反映される）
- 入力中・曖昧・未解決のトークンは、打った文字列のまま保存し、起動時に解決し直す
- 端末間では同期しない（見ている画面は端末ごとの状態のため）
- 保存は入力のたびではなく、変更が 1 秒止まったとき、および終了時に行う
- 追加先ピッカーの「最後に使った追加先」「最近使った追加先」も同じ場所に保存する

### 7.3 その他

| 項目 | 案 |
| --- | --- |
| 空のクエリ | 全プロジェクトの全タスク（完了済みを含む）を表示する |
| タグ管理の「選択中プロジェクト」 | 内部クエリにプロジェクトの参照が 1 つだけあればそれ、そうでなければ選択中タスクのプロジェクト |
| タグブックマークのクリック | 現行は所属プロジェクトへ移動して `#名前` を適用している。プロジェクト選択がなくなるので `#名前` を書き込むだけにする |
| 並び替え（D&D） | 現行どおり「手動」ソートのときだけ |
| 検索結果 0 件 | 既存の空状態（「検索条件をクリア」）を使う |

## 8. 実装方針（概略）

### 8.1 モジュール

検索のルールは `crates/flequit-ui/src/viewmodels/search/` に置く。いずれもウィンドウなしでテストできる純粋な処理とする。

| モジュール | 役割 |
| --- | --- |
| `normalize` | 比較用の畳み込み（NFKC + 小文字化）、全角記号の読み替え、名前の引用 |
| `vocabulary` | 5.1 の語彙表（状態・種類名・テキスト属性）と UI 言語 |
| `due` | 期限キーワード。名前付き / 日数 / 分数を区別して持ち、全言語の表記を読み、UI 言語で書く |
| `lexer` | トークン化（各トークンの範囲を保持）と、1 語の解釈（`@` / `#` / 自由語 / 引用） |
| `resolve` | 参照（`Reference`）と名前索引。名前 → 候補、参照 → 表示トークン |
| `document` | 表示文字列と確定済み参照の対応（セグメント列）。編集への追従、確定、改名・言語切替の作り直し、内部クエリの入出力 |
| `parser` | 3.3 の文法で条件木を作る。誤りは 3.6 のとおり回復し、報告する |
| `eval` | 残った名前を引き、タスク / サブタスク 1 件ずつを判定する（3.7） |
| `sidebar` | サイドバー操作（置き換え / AND / OR / NOT / 取り除き）とハイライトの導出 |
| `suggestion` | 入力候補と曖昧さ解消の候補 |
| `session` | 上記をまとめた検索ボックスの状態。ViewModel はこれだけを使う |

Slint との橋渡しは `crates/flequit-ui/src/viewmodels/app/query.rs` が担う
（検索ボックスの公開、サイドバーのハイライトと件数、タスク一覧の再構築、追加先ピッカー、保存）。

### 8.2 入力欄と対応表の同期

Slint の `LineEdit` は文字列しか持てず、範囲に隠しデータを付けられない。そのため対応表は ViewModel が持つ。

- 入力のたびに、前回と今回の文字列の共通の前方・後方を比べて変更範囲を求める。
  変更範囲の外の確定トークンはそのまま残し、重なった確定トークンは確定を外す
- 確定トークンの直前・直後に空白や演算子なしで文字が付いた場合も確定を外す（`@仕事x` は別の語になるため）
- アプリがクエリを書き換える操作（サイドバー、候補の確定、改名追従）は、セグメント列を直接作り直し、
  キャレットを末尾へ移すよう UI へ知らせる

### 8.3 既存コードへの影響

- `SharedState` の `selected_project_id` / `selected_list_id` による絞り込みは廃止した。
  `AppState.selected-project-id` は、タグ管理と「リスト作成」が対象にするプロジェクトとして、
  クエリ → 選択中のタスク → 追加先の順に導出する
- サイドバーの選択系アクション（`select-project` / `select-task-list` / `due-filter-clicked` /
  `select-tag-bookmark`）は `apply-filter(種類, キー, 操作)` にまとめた
- `TaskItem` に `search-dimmed` / `matched-subtask-count`、`SubTaskItem` に `search-match` を加えた
- ユーザー一覧（`user_facades::list_users`）を起動時に読み込み、`@user` の解決に使う
- クエリと最近の追加先は `UserSettings` の `search_query` / `recent_add_targets`
  （設定ファイルでは `searchQuery` / `recentTaskDestinations`）に保存する
- 名前の正規化に `unicode-normalization` クレートを使う（依存ツリーには既に含まれていたものを直接依存にした）

### 8.4 テスト観点

- 優先順位: `A | B C` = `A | (B C)`、`-A B` = `(NOT A) B`
- 回復: `(A | B` / `A |` / `| A` / `)A` / `()` / `@` / `-`
- 全角: `＠今日｜＃仕事`、全角空白区切り
- 解決: 候補 1 つで確定、複数で曖昧、`@P.L` の分割、種類の明示と `*` の和集合
- 対応表: 前後の編集で範囲がずれること、確定トークン内の編集で確定が外れること、貼り付けが入力中になること
- 往復: 内部クエリ → 表示 → 内部クエリが一致すること、全言語で表示を作れること
- 改名・削除・言語切替で表示だけが変わり、自由語が変わらないこと
- AND / OR / NOT 追加の括弧補完、トグル、クリア。同名の別プロジェクトを別物として扱うこと
- ハイライト: AND 項は強く、OR 項は弱く、同名の片方だけが光ること
- 状態キーワード: `@未完了` が完了と中止を除くこと
- サブタスク: 期限・状態・担当は継承しないこと、所属・タグ・自由語は継承すること、
  1 件の中で全条件を満たす必要があること、サブタスクだけが当たったタスクの行が薄く表示・自動展開されること
- 追加先の既定値の決まり方と、手で選んだ値がクエリ変更で上書きされる条件
- 入力候補の表示中もフォーカスが検索ボックスに残ること（続けて入力でき、← でキャレットが動き、↓ + `Enter` で選べる。
  `tests/interaction.rs` の `search_suggestions_leave_focus_in_the_field`）

## 9. 判断の経緯

| 論点 | 決定 | 理由 |
| --- | --- | --- |
| 絞り込みの状態 | サイドバーの選択状態を廃止し、クエリだけにする | 選択とクエリの 2 系統が食い違う状態をなくす |
| 同名のプロジェクト | 許す | リストやユーザーでも別プロジェクト間の同名は自然に起きる |
| 同名の区別 | ID は見せず、候補から選ばせて内部の参照で保持する | ID は多くの利用者に馴染みがない |
| `@名前` の範囲 | 期限 / 状態 / プロジェクト / リスト / ユーザーを探し、複数なら一覧から選ぶ | 短く打てることと、データ上の明確さを両立する |
| 候補一覧の出し方 | ポップアップではなく検索ボックスの直下にインライン表示 | `PopupWindow` はフォーカスを奪い、入力の途中でキャレットが外れる |
| ユーザーの内部参照 | `UserId` | `handle_id` を変更可能にする可能性がある |
| タグ | 本仕様の対象外（`#タグ名` の前方一致のまま） | `#` で入力するもので、`@` の仕組みとは別 |
| `@project:` / `@list:` | 完全一致。部分一致は `*` | 省略形 `@X` と同じ規則にそろえる |
| OR 追加の修飾キー | Alt / Option | Shift + クリックは範囲選択の慣習と衝突しうる |
| NOT | 入れる | 「保留を除く」「完了を除く」の用途が大きい |
| 完了済みの既定の見せ方 | 空のクエリでは出す。状態ボタンで絞る | クエリ以外に隠れた条件を作らない |
| サブタスク | 1 件の検索対象として評価する。期限・状態・担当は継承しない | 「今日が期限のサブタスク」を正しく拾う |
| クエリの保存 | 内部クエリを端末ごとの設定へ保存する | 再起動後も同じ一覧を開ける。言語や改名に依存しない |
